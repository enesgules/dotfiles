## Core values

1. **Expected failures are typed. Defects are bugs.** "Expected service failures live on the Effect error channel." ([errors.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/errors.md)). "`Effect.die(...)` is reserved for defects: bugs, impossible states, violated invariants, and final unknown-boundary fallbacks." ([errors.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/errors.md)). "Do not use `throw`, `Effect.die(...)`, or `catchDefect` for expected user, IO, validation, missing-resource, auth, provider, worktree, or busy-state failures." ([errors.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/errors.md)). The test for which one: "But tracking only matters if recovery is possible." ([effect-solutions, Error Handling](https://github.com/kitlangton/effect-solutions/blob/HEAD/packages/website/docs/06-error-handling.md)).
2. **Catch only when you have a true answer.** "Catch or retry only when the current boundary has a truthful response." and "Let exhausted failures remain visible unless the boundary has a real fallback." ([Effect skill](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/SKILL.md)). In review: "I feel like these should throw instead of falling back to `Instance`." and "instance ref should have been set up correctly, otherwise it's an architectural issue." ([opencode#20304](https://github.com/anomalyco/opencode/pull/20304#discussion_r3018145498)). On a PR that stripped bad config: "The intentional behavior is to surface bad configs loudly so users fix them, not silently strip them." ([opencode#26611](https://github.com/anomalyco/opencode/pull/26611#issuecomment-4414098316), agent-written style).
3. **Each seam owns its error shape.** "The important rule: a service error should not also be the HTTP body, CLI formatter, and session event body." and "Each seam adapts the error into the shape it owns." ([error-boundaries-plan.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/error-boundaries-plan.md)). "Do not create one giant `unknown -> status` mapper." ([errors.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/errors.md)).
4. **Types you can trust.** "And once you've fully acclimated to the fact that you cannot fully trust your type system, it is difficult to imagine a paradigm in which you can" ([post, 2026-01-09](https://x.com/KitLangton/status/2009712067972825209)). "I enjoy writing beautiful code, and the more I can trust the type system to have my back, the more freedom I have in refactoring." ([same post](https://x.com/KitLangton/status/2009712067972825209)). "Do not use `as any`, non-null assertions, or unchecked casts to silence Effect typing problems." ([Effect skill](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/SKILL.md)).
5. **Decode unknown data with Schema, once.** "Decode unknown wire input with `Schema.decodeUnknownEffect(...)`; use `schema.makeEffect(...)` for typed constructor input with validation." and "never use casts to skip validation." ([Effect skill](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/SKILL.md)).
6. **Effect only where it does effectful work.** "What's the point of wrapping these in effect if they're synchronous functions?" ([opencode#20374](https://github.com/anomalyco/opencode/pull/20374#discussion_r3022123165)). "Service wrapper adds no state, no mockability, and no consumers for the new `readFile`/`parseText` methods." ([opencode#27147](https://github.com/anomalyco/opencode/pull/27147#issuecomment-4446298171), agent-written style).
7. **Readable for the team, not clever.** On a terse `Schedule` combinator: "It's very cool but also a little scary to consider suggesting to my effect noob teammates" ([effect-smol#1946](https://github.com/Effect-TS/effect-smol/pull/1946#issuecomment-4169735965)).

## Review checklist (what he checks or pushes back on)

**Error channel**
- Typed domain errors with `Schema.TaggedErrorClass`: "Use `Schema.TaggedErrorClass` for expected domain failures." and "Put expected errors in service method signatures." ([errors.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/errors.md)). "Do not hand-roll `_tag` error classes when `Schema.TaggedError` fits." ([Effect skill](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/SKILL.md)).
- Yield the error, do not wrap it: "Use `yield* new DomainError(...)` for direct early failures in `Effect.gen` / `Effect.fn`." ([errors.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/errors.md)).
- Recover by tag: "Do not use cause-level recovery when typed-error recovery is enough." ([Effect skill](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/SKILL.md)). In v4, `catchAll` is `Effect.catch`: "`Effect.catch`; prefer `catchTag` for selected tagged errors" ([V4_APIS.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/V4_APIS.md)). One handler for several tags: "Effect supports catching a non-empty tag list with one narrowed handler." ([opencode#45722](https://github.com/anomalyco/opencode/pull/45722), PR body, likely agent-drafted).
- Translate with `mapError`, not catch-and-fail. Lint rule: "Use mapError instead of catching only to fail with a transformed error." ([no-effect-catch-fail.yml](https://github.com/anomalyco/opencode/blob/314842df119544845441fe6f7a3dec0bba857624/script/ast-grep/effect-simplifications/rules/no-effect-catch-fail.yml)). Why: "Immediate `catch` handlers that only transform an error and fail again obscure the error-channel-only operation." ([opencode#46028](https://github.com/anomalyco/opencode/pull/46028), PR body, likely agent-drafted).
- A constant fallback is written as such. Lint rule: "Use Effect.orElseSucceed for constant failure recovery." ([no-effect-catch-succeed.yml](https://github.com/anomalyco/opencode/blob/314842df119544845441fe6f7a3dec0bba857624/script/ast-grep/effect-simplifications/rules/no-effect-catch-succeed.yml)). Inference: the rule makes a swallowed failure easy to see in a diff. Standard 2 still decides if the fallback is allowed.
- A defect is a real `Error`. Lint rule: "die with `new Error(...)`." ([no-effect-die-string.yml](https://github.com/anomalyco/opencode/blob/314842df119544845441fe6f7a3dec0bba857624/script/ast-grep/rules/no-effect-die-string.yml)).
- Keep the cause: "Use `Schema.Defect()` for defect-like payloads." and "Include operation labels when they help diagnose adapter, persistence, provider, or transport failures." ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)). "Use `Schema.Defect` for opaque error payloads instead of `Schema.Unknown`." ([opencode#27403](https://github.com/anomalyco/opencode/pull/27403), PR body). Bug report: "Expected the script failure to preserve the operation and HTTP error/cause." ([opencode-drive#71](https://github.com/anomalyco/opencode-drive/issues/71#issuecomment-5518862078), agent-written style).
- Name the real failure: "Nothing failed to parse. The connection was reset while the response body was being read." ([opencode#52634](https://github.com/anomalyco/opencode/pull/52634), PR body, likely agent-drafted).
- Never classify errors by message text: "The remaining error classification relies on matching error-message strings, which is too fragile to adopt as the HTTP error boundary." ([motel#7](https://github.com/kitlangton/motel/pull/7#issuecomment-4810881778)).
- Fix the type, not each handler: "Typed errors at the service boundary auto-route status + body via HttpApi schema annotations. No wrappers, no forgetfulness possible." ([opencode#25533](https://github.com/anomalyco/opencode/pull/25533#issuecomment-4365329596), agent-written style).
- Promise rejections: "Use `Effect.tryPromise({ try, catch })` when every rejection should become the same expected error type." and "Use `Effect.promise(...)` only when rejection means a defect and you do not need to refine known rejection classes." ([error-boundaries-plan.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/error-boundaries-plan.md)).
- `orDie` only where nothing can recover. His guide uses it at app start for config: "At app entry: if config fails, nothing can proceed" ([effect-solutions, Error Handling](https://github.com/kitlangton/effect-solutions/blob/HEAD/packages/website/docs/06-error-handling.md)). In opencode, on a fetched catalog: "deliberate: loud failure over silently mistyped catalog data" ([opencode#35174](https://github.com/anomalyco/opencode/pull/35174), PR body).

**Schema and data**
- Decode, do not cast. Lint rule: "Prefer Effect Schema JSON decoding over JSON.parse casts." ([no-json-parse-cast.yml](https://github.com/anomalyco/opencode/blob/314842df119544845441fe6f7a3dec0bba857624/script/ast-grep/rules/no-json-parse-cast.yml)). In review: "no casts" ([opencode#16956](https://github.com/anomalyco/opencode/pull/16956#discussion_r2915530499)) and "I don't think this `as` is necessary." ([effect#5853](https://github.com/Effect-TS/effect/pull/5853#discussion_r2616616951)).
- Throwing decoders only where throwing is fine: "Use `Schema.decodeUnknownSync(...)` only in scripts, tests, or startup paths where throwing is acceptable." ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)).
- Records: "Default to `Schema.Struct(...)` plus a same-name `interface`." ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)). "Do not introduce `Schema.Class` or `Schema.TaggedClass` as default app data-modeling patterns." ([Effect skill](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/SKILL.md)).
- Variants: "Prefer a principled split over forcing one representation everywhere: Data internally, Schema at boundaries." and "Do not add a Schema solely to obtain these utilities." ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)).
- Brands: "Use constrained branded schemas for scalar IDs and value objects." ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)). In review: "Once you have the other stuff from dev you can use the `Newtype` pattern for the ID :D" ([opencode#17814](https://github.com/anomalyco/opencode/pull/17814#discussion_r2956961184)). The same PR made event IDs with the wrong prefix; his fix was a one-line suggestion that gives `Identifier.ascending` the event prefix ([opencode#17814](https://github.com/anomalyco/opencode/pull/17814#discussion_r2956956442)). - Optional fields: "Use `Schema.optionalKey(...)` for absent JSON/storage keys." and "Do not make domain values optional merely for construction convenience." ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)).
- No `Any`: "Current public contracts avoid `Schema.Any`." and "Use `Schema.Unknown` for genuinely opaque values that require consumer-side narrowing." ([schema AGENTS.md](https://github.com/anomalyco/opencode/blob/314842df119544845441fe6f7a3dec0bba857624/packages/schema/AGENTS.md)).
- One schema per concept: "Use one canonical exported value for each contract." and "Preserve a single canonical event definition." ([schema AGENTS.md](https://github.com/anomalyco/opencode/blob/314842df119544845441fe6f7a3dec0bba857624/packages/schema/AGENTS.md)). ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)).
- Option and Result from Schema: "Use `Schema.decodeUnknownOption(...)` only when mismatch details are intentionally discarded." and "Use `Schema.decodeUnknownResult(...)` for pure code that wants explicit success/failure without Effect." ([SCHEMA.md](https://github.com/kitlangton/skills/blob/HEAD/skills/effect/references/SCHEMA.md)).

## Tone and phrasing

## Hard "no"s / pet peeves

- Casts instead of decoding (`as`, `JSON.parse(x) as T`).
- A fallback that hides a broken invariant (`?? Instance`, strip bad config).
- Error classification by message string.
- One generic mapper or middleware that knows all domain errors: "Do not grow generic HTTP middleware into a registry of domain errors." ([errors.md](https://github.com/anomalyco/opencode/blob/1a08e321c5f473a24d6d4c48383639751baeea75/packages/opencode/specs/effect/errors.md)).
- `Effect.die` with a string, catch-then-fail, identity pipes, nested service yields (his CI lint rules).
- Effect wrappers around sync code, and service wrappers with no state, mock, or consumer.

## Heuristics that generalize (incl. TypeScript web apps)

1. Ask: can a caller recover? If yes, a typed error in the signature. If no, a defect with `new Error`.
2. A catch that returns a value needs a boundary with a true answer. Else let it fail.
3. Map errors at the seam that owns the output shape (HTTP, CLI, event). The service error stays transport-free.
4. Unknown data meets a Schema once. After that, code trusts the type and does not check again.
5. `Schema.Struct` plus interface for records, `Data.TaggedEnum` for internal states, `Schema.TaggedUnion` for unions that cross a boundary.
6. `Effect.fn('Domain.op')` for service methods, so the trace names the work. `fnUntraced` for small helpers.
7. Turn a repeated review comment into a lint rule with a safe autofix (his ast-grep work).
